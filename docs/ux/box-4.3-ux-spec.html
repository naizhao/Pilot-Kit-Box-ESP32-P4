15 · 术语：TARE → LEVEL / 调平（已定）

你的类比很准 —— 「上飞机后把罗盘物理拨杆往外拔」，那个动作在航空术语里叫 caging（笼锁）。 而 TARE 来自称重行业的「去皮」，飞行员并不熟悉。现有实现也确实是 cage 语义 （pfd_attitude.c 只 cage 横滚 / 俯仰，航向解耦）。

方案英文中文说明
✅ A（已采用）LEVEL调平现代 EFIS 通用叫法（Dynon SkyView 即为 Level）；「调平」直观、2 字、dock 放得下
BCAGE锁定 / 笼锁最贴合传统陀螺仪，老飞行员一看就懂；但年轻用户可能陌生，中文「锁定」易误解为锁死
CZERO归零最直白；但「归零」在航向语境下有歧义（本功能不动航向）
DTARE校零维持现状，代码零改动；但术语与航空语境脱节

✅ 已采用方案 A，本稿 dock 与四态图均已替换为「调平」。 涉及改动：i18n_catalog.py 加词条 → 重跑 gen_i18n_assets.py 生成字形 （否则中文渲染成 ?）· dock 动作区宽度按最终字数复核。

16 · 预览校准说明（防止实施时吃不准）

本稿绘制单位毫米（mm），非像素。所有 .scr 容器 = 93.7 × 56.2 mm
换算基准800 px = 93.7 mm → 1 px = 0.1171 mm · 8.54 px/mm · 217 PPI
为何需要校准CSS 规范固定 1mm = 3.7795 CSS px（96 px/inch），与真实显示器 DPI 无关。 高分屏上不校准会显示成实际的 38%~75%
设计者显示器3008 × 1692 逻辑分辨率（2026-07-27 记录）
对应缩放系数14″ 约 2.64× · 16″ 约 2.31× · 24″ 约 1.50× · 27″ 约 1.33×
校准方法页首滑块 + 信用卡实测（85.6 × 54.0 mm），结果存 localStorage['pkbox-cal']
实施时以什么为准以像素值为准（表格中括号内数字），mm 仅用于人眼校验尺度感。 例：正文 26 px、看板行高 48 px、dock 高 56 px
